# Provider infrastructure inventory (`src/lib/providers/`, `infra-sync.ts`, `infra-pricing.ts`, `infra-gold.ts`, `fx-rates.ts`, `infra-cron.yml`)

The fleet buys domains and mailboxes from FOUR vendors: **Gandi** (3 organisations), **Mailforge**, **Primeforge**, **Instantly DFY**. `POST /internal/infra/sync` (platform-scoped, `serviceAuth`, daily 05:00 UTC `infra-cron.yml`) polls all four into bronze (`provider_domains_raw`, `provider_mailboxes_raw`, `provider_account_raw`), upserts silver `infra_domains`/`infra_mailboxes`, flags rows a vendor stopped reporting. Pure normalisers exported and tested (`provider-clients.test.ts`). Spends nothing metered (flat subscriptions).
- **`(provider, domain)` is the primary key, NOT `domain`** (a domain can be reported by two vendors; do NOT add a `primary_provider` column). **Rows are flagged absent (`absent_since`), never deleted** (same for `instantly_accounts.absent_since`); a ghost in a non-sending state is a counting error, not a capacity error (first run flagged 13 of 266, none `in_production`).
- **A DFY domain carries N ORDER ROWS, COLLAPSED before emission (`collapseDfyOrders`): a domain is `cancelled` only when EVERY row is** (Instantly splits a domain when one mailbox is cancelled, the cancelled row comes LAST, and the upsert on `(provider, domain)` lets it win, so a live domain read as deprovisioned and was offered for deletion; `vibrancesense.com`, 2026-09-13). One active row keeps the domain active (overstating cost beats deleting live senders); cancellation date = LATEST row's, `createdAtProvider` = EARLIEST. Only DFY is order-based. Guard `collapseDfyOrders` in `provider-clients.test.ts`.
- **The absence sweep runs ONLY for a vendor whose fetch SUCCEEDED** (Gandi scoped to the reporting org); keys on `last_seen_at`, never a `NOT IN (...)` list (65,534-parameter ceiling). One vendor failing does not stop the others (`failures`); the run throws only when EVERY vendor failed; an empty Instantly account list throws.
- Keys (key-service platform keys): `gandi-org1`, `gandi-org2`, `gandi-org3`, `mailforge`, `primeforge` (+ existing Instantly); `resolvePlatformKey(provider)` in `key-client.ts`.
- **Vendor API gotchas (probed live 2026-08-02; the docs/skills were wrong on two)**: Gandi `Bearer <token>`, one token per org (403 on an email route = wrong org token), `page`+`per_page` 100, price `/domain/check?processes=renew` per domain in EUR. Mailforge `Authorization: <key>` RAW (Bearer and `X-Mailforge-Key` fail; the REST host is the ONLY place `priceCents` appears), `limit`+`offset` 100 max, USD. Primeforge `Authorization: <key>` RAW, distinct key, `limit=200` returns an EMPTY list rather than erroring, NO billing API (all 404): rate card only. Instantly DFY the platform Instantly key, `next_starting_after`, rate card. `GET /dfy-email-account-orders` reports the provisioning class per domain (`provider_code` is the connection PROTOCOL: 1 IMAP, 2 Google); a cancelled order keeps its row with `cancelledAt` (a dead domain is still a cost).
- **Cost lives HERE and, since the rebill stopped, is the ONLY place cold-email spend is measured.** `infra_price_rates`: what the vendor charges US, `source` (`api`|`rate-card`), currency, `effective_from` (non-retroactive: a rate change ADDS a row). Cost per email = `/internal/infra/spend` / real `email_sent` events, NOT a catalog lookup (a per-org stat with zero Instantly spend is correct).
- **`billedMailboxCount` (`infra-pricing.ts`): DFY is the single exception** (its mailboxes ARE the Instantly accounts and the adapter emits none into `infra_mailboxes` to avoid double counting, so `mailboxCount` = 0 silently dropped the $10/mailbox/month line: `/spend` showed $11.25/mo vs real ~$431). For other vendors the count comes from `infra_mailboxes` (we pay for what the VENDOR hosts: 42 Gandi mailboxes vs 165 Instantly accounts). Do NOT generalise or "fix" by emitting DFY mailboxes. Guard `billedMailboxCount` tests (pin the Gandi non-generalisation).
- **Two price sources coexist**: vendor-reported per-DOMAIN `infra_domains.price_cents` (treated as YEARLY: Mailforge and Gandi quote a renewal) and the rate card. `monthlyCostForDomain` = vendor price + `mailbox-month x VENDOR mailbox count`. **Primeforge priced from its PUBLISHED PAGE** (migration `0034` mirrors it into bronze `provider_account_raw` scope `pricing-page`): $14/yr per domain, **$4.50/mo per SLOT** (monthly list rate, not the discounted annual $3.75: overstating is the safe direction; a slot, not a live mailbox, so a deleted mailbox keeps costing until released). If annual, ADD a row with a new `effective_from`, never edit. **Do NOT seed a rate for an unsourced vendor.** A cancelled domain prices to null.
- **Gold reads (cached via `getOrSetCachedStats`)**: `GET /internal/infra/domains`, `/waste`, `/spend`. **`/waste` is REPORT-ONLY** (never cancels an autorenew or schedules a deletion; brand domains are held on purpose). **Totals per currency AND in USD at a named ECB rate (`src/lib/fx-rates.ts`, table `fx_rates`, migration `0059`)**: Gandi bills EUR, summing native cents mislabelled euro as USD ($898.07 shown vs $933.14, 2026-09-22). One rate EUR to USD (ECB daily reference, keyless), append-only per day, fetched at the end of `/internal/infra/sync` and by `POST /internal/infra/fx-sync` (synchronous). Domain reads carry a top-level `fx` (rate, day, source) and a `usd` twin per native amount; `/spend` adds `monthlyTotalUsdCents` = sum of PER-DOMAIN USD figures (never one conversion per currency total: 3 cents off on the live estate). **NO fallback rate**: no rate = `fx` null and EUR `usd` twins null (a consumer treats null as "cannot state this total", never zero). Per-email USD from USD monthly / sends. A domain with `absent_since` prices to null on the domain reads (as `/spend` already skipped). Verified 2026-09-24: `/internal/ops/domains` sum `cost.usd.monthlyCents` == `/spend` `monthlyTotalUsdCents` == $927.66. Cost per email is a FLOOR while `unpricedProviders` is non-empty.
- **`vendorReportsMailboxes(provider)`** (`infra-pricing.ts`, same fact as `billedMailboxCount`'s `BILLED_PER_INSTANTLY_ACCOUNT`): whether `vendorMailboxes` means anything (DFY's 0 means "not reported"); a separate field because the dashboard parses `vendorMailboxes` as `z.number()`. Mailforge's zeros are REAL (five `not_paid` domains).
- **Sends are counted per DOMAIN, not per inventory row** (a two-vendor domain would double the denominator). **`/domains` reports cost TWICE**: blended `monthlyCostCents` and split by when cancelling saves it (`recurringMonthlyCents` immediately / `renewalCents` YEARLY + `renewalAt` at next renewal; `splitDomainCost`); do not "fix" the yearly/monthly inconsistency.
- **`lifecycle-cron.yml` is the SOLE caller of `/internal/audit/accounts-sync`** (hourly); `accounts-sync-cron.yml` was deleted (was ~37 runs/day from three schedules). Do not re-add it elsewhere.
