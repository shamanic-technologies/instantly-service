# Routes: audit, forecast, reconciliation, stats gold (`src/routes/audit.ts`, `analytics.ts`, `analytics-public.ts`, `status.ts`)

**Sending forecast** `GET /internal/audit/sending-forecast` (same `serviceAuth` tier as `/internal/accounts`). Pure logic `src/lib/sending-forecast.ts` (`tests/unit/sending-forecast.test.ts`), route IO only.
- **Cached and the config LATERAL is INDEXED; do NOT unwrap either.** 60s `getOrSetCachedStats`; `loadPendingLeads` per-lead latest-config LATERAL is served by `instantly_campaigns_config_raw(instantly_campaign_id, fetched_at DESC)` (migration `0026`, `CREATE INDEX IF NOT EXISTS`, ~550k rows/1.4GB so pre-built CONCURRENTLY out-of-band; any new prod-scale env must do the same before deploy). Loader throw caches nothing (fail-loud).
- **Capacity** (`dailyCapacity`, `healthyAccountCount`, `totalAccountCount`, `blockedDomainCount`) via `computeCapacitySummary(accounts, lifecycleByEmail, volume, mailboxOf)`. `dailyCapacity` is what the fleet can REALLY send today, NOT `sum(daily_limit)`: it sums over real MAILBOXES (operator limit = MIN across a mailbox's aliases, ramp = the mailbox's own summed volume via `loadMailboxLogins` + `fetchRecentDailyVolume`). The VOLUME group is every address that authenticates as the mailbox (aliases in recovery and seed mail spend the same relay quota); the LIMIT group is production-only. Unknown login = its own mailbox (never dropped). `healthyAccountCount` stays an ACCOUNT count. `blockedDomainCount` = `deactivated_by_user` accounts. Near-zero capacity under a halt is legitimate, never fabricate. Cost 2026-09-08: page read 2,980/day vs 1,696 ramped.
- **Volume** (`days[]`) `projectDailySchedule(pendingLeads, asOf)`: capacity-INDEPENDENT per-day projection of remaining un-sent steps (`sequence_costs status='provisioned'`, live campaigns: `instantly_campaigns.status='active'` AND `delivery_status IN ('contacted','sent')`). Cadence = real per-step delays from bronze config (`PendingLead.stepDelays`, same indexing as `queue-breakdown.ts`), `STEP_GAP_CALENDAR_DAYS = 3` only as the missing-delay fallback. **Day bucket = raw nominal UTC send day, NO weekend snap** (identical to the queue breakdown so the two staff surfaces reconcile); do NOT reintroduce a snap or a hardcoded gap. It is a nominal-cadence lower bound.
- **Key resolution**: shared workspace key from key-service `GET /keys/platform/instantly/decrypt` (`resolvePlatformInstantlyApiKey`, `key-client.ts`). No `process.env.INSTANTLY_API_KEY` on the request path (CLI override only). 404 fails loud 500.

**Reconciliation audit** `GET /internal/audit/reconcile`: `src/lib/reconcile-audit.ts`. Returns `{key,label,local,instantly,delta,sourceOfTruth}` (`delta = local - instantly`); Instantly is SoT.
- **Counts only, never future DATES** (the exact send date exists nowhere). **Exactly THREE metrics: `activeCampaigns`, `emailsSent`, `pendingSends`.** `contactedDispatched` (Instantly `contacted_count` tracks dispatches, local counts distinct leads) and `contactsStored` (local never decrements, Instantly drops as finished-contact cleanup deletes) were removed because their delta is structural; do NOT re-add (still computed, snapshot keeps 5 columns).
- **`pendingSends` counts STEP-SENDS and is derived on Instantly**: sum over ACTIVE campaigns of `max(0, stepCount - sent)` (`computeInstantlyPendingSends`). Local = `COUNT(DISTINCT (campaign_id, lead_email, step))` provisioned holds, NOT `COUNT(*)` (pre-`0038` rows are doubled). Do NOT mark it local-only.
- Instantly side = two bulk sweeps (`listAllCampaignAnalytics`, the ONE deliberately non-paginated helper; `listAllCampaignSequenceLengths`, paginated). **NEVER swept live in the GET**: it is a pre-aggregated single-row snapshot `instantly_reconcile_snapshot` (migration `0022`, PK `'singleton'`), `src/lib/reconcile-snapshot.ts`. Refresh: `POST /internal/audit/reconcile/refresh` (202, seed after deploy, cron) and stale-while-revalidate on read (`RECONCILE_SNAPSHOT_TTL_MS` 30 min, in-flight flag). Missing snapshot = 503 + kick refresh, never a fabricated zero.
- **Orphaned-hold repair** `POST /internal/campaigns/actualize-orphaned-sends` (`src/lib/actualize-orphaned-sends.ts`): actualizes `provisioned` holds whose step already has a real (`inferred=false`) `email_sent` event (transient runs error swallowed the actualize). A hold whose run is GONE (runs 404, `isRunGoneError` in `runs-client.ts`, 404 only) is cancelled LOCALLY, counted `costsCancelled`; transient 5xx/timeout/403 stays `provisioned` (`costsTransient`). Summary `{stepsProcessed, costsActualized, costsCancelled, costsTransient, stepsFailed}`, `{limit}`. Wired into the daily `reconcile-cron.yml` step 2 (03:00 UTC).
- **A provisioned hold on an Instantly-ACTIVE campaign is correctly IN-FLIGHT; never blanket-cancel or blanket-actualize.** `POST /send` provisions ALL steps' holds upfront and marks each step-run `completed` at /send time (run completed is not email sent); forecast, queue breakdown, account selection and `queueSize` all read `provisioned` as the scheduled-unsent set. A hold resolves only by `email_sent` (actualize) or a terminal sequence (cancel via `cancelRemainingProvisions` / reconcile finish-closure).
- Known gap: nightly `reconcileAll` is fire-and-forget with no time cap and covers ~10k of ~11.3k active campaigns; the 3 deltas do not zero nightly. Levers: run the cron 2-3x/day, handle the null-analytics early return, make the sweep resumable.

## Finished-contact cleanup and reconcile coupling

Instantly's plan limit counts contacts CURRENTLY stored across all campaigns (each duplicate counts separately); **only a campaign-level `DELETE /leads {campaign_id, delete_list}` frees quota** (~5-10 min). Each send is its own per-lead campaign, so a finished one (Instantly status paused 2 / completed 3; active 1 never touched; no pause grace period, locked option A) is deletable with no data loss (history is in silver).
- One-shot `cleanup:finished-contacts` (pure `src/lib/cleanup-finished.ts` `selectContactsToDelete`/`countDeletions`, `FINISHED_STATUSES = {2,3}`; script does Instantly IO only; 404 delete counted not fatal).
- **Recurring (nightly `reconcileAll` / `reconcileOneCampaign`, `src/lib/reconcile.ts`; pure `src/lib/finished-contacts.ts`)**: Phase 0 already reads the campaign status (`parseInstantlyStatus`). **ORDERING INVARIANT: status read in Phase 0, delete executes LAST via the `finish(result)` closure** (after analytics + `/leads/list` + `/emails` backfill; a late reply is never dropped). **COST-CANCEL INVARIANT: in the same `finish`, for a finished campaign FIRST `cancelRemainingProvisions` (refund) THEN delete the contact (`deleteFinishedContact` sets local status to completed 3 / paused 2 via `localTerminalStatus`)**; the cancel is INDEPENDENT of `DELETE_FINISHED_CONTACTS_ENABLED` (without it ~12k holds stranded on terminal campaigns, fixed 2026-06-27 #334/#335) and must not move out of `finish`. Pre-fix backlog drained once by `POST /internal/campaigns/refund-stranded-holds` (`src/lib/refund-stranded-holds.ts`; 202 + background, `{limit}`, log `refund-stranded-holds: done`). `reconcileAll` skips locally-terminal rows when deletion is enabled (`isLocallyTerminal`). 404 tolerated (`isLeadAlreadyGone`); other errors counted `failed`, retried next run; no cost declared.
- **`DELETE_FINISHED_CONTACTS_ENABLED=true` in prod since 2026-06-13**: any paused campaign (including a manual pause-to-edit or an Instantly auto-pause) has its contact deleted irreversibly at the next 03:00 UTC reconcile. Only pause when you mean "done". Disarm in `/root/distribute/env/instantly-service.env` (runtime var, no rebuild).

## A dispatch BACKLOG drains itself; the thing that never drains is a sequence pinned to a deleted mailbox
Overdue steps are NOT a bug: the fleet is capacity-bound (`dueBeforeCapacity: 1431 -> due: 406` is normal), nothing goes out at weekends, owner: late days just mean the accounts are oversubscribed and it clears itself. **The discriminator is whether the pinned `account_email` still EXISTS at the vendor** (a followup is pinned for life, persist-at-write `0025`); steps pinned to a deleted mailbox hold `provisioned` rows forever (`reconcile-provisioned-holds` SKIPs in-flight). Fix = PAUSE their Instantly campaigns (nightly `finish` refunds holds and marks terminal), **never re-arm `retry-stuck`** (`RETRY_STUCK_WORKER_ENABLED=false` in prod; re-arming would redispatch ~448 never-contacted Instantly sequences fleet-wide, a volume decision; its gate is `delivery_status='contacted'`). A paused lead is not re-servable for 3 months (human-service suppression from the original serve).


## Data layering (B/S/G; doctrine in the `data-layering` skill) and gold stats
- **Bronze** raw append-only mirrors: `instantly_webhook_payloads_raw`, `instantly_analytics_raw`, `instantly_emails_raw`, `instantly_leads_raw`, `instantly_campaigns_config_raw`, provider mirrors. **Silver**: `instantly_events` + `instantly_campaigns`, `infra_domains`/`infra_mailboxes`, derived via `src/lib/silver-promote.ts` / `infra-sync.ts`, rebuildable. **Gold**: `analytics.ts`, `status.ts`, read silver only.
- **Reply-sentiment gold = CURRENT sentiment (latest event per lead), NOT raw event counts**: `DISTINCT ON (campaign_id, lead_email) ... ORDER BY timestamp DESC, (source='manual') DESC, created_at DESC, id DESC` CTE in `queryGroupedSentiment`/`querySentiment` (merged into `repliesDetail` by `queryGroupedStats`/`queryStats`; both routers `analytics.ts`, `analytics-public.ts`). A raw `COUNT(*) FILTER (WHERE event_type='lead_interested')` never drops a stale positive after re-qualification. Silver keeps the full history; do NOT delete/mutate silver on reclassification. `unsubscribe` stays an event count. **Per-step sentiment = current sentiment on the LAST step** (`queryStepSentiment`, `MAX(step)` of `email_sent`); step-level email metrics stay per-step. Guards: `stats.test.ts`, `stats-public.test.ts`, `tests/integration/sentiment-reclassify.test.ts`.
- **`delivered` is counted in SQL, attributed to the SEND, never `sent - bounced`**: 491 of 2,425 bounces (20.2%) land in a different bucket than their send, so subtraction went negative (`delivered: -2`) and shifted yesterday's bounces onto today. **`Math.max(0, ...)` is forbidden.** Fragments `DELIVERED_AGGREGATES`/`BOUNCED_STEP`/`BOUNCED_LEAD` (`analytics.ts`): email delivered = its own `(campaign, lead, step)` has no bounce; recipient = `(campaign, lead)` has none. Bounce sets LEFT JOINed once per statement via `BOUNCE_JOINS` (place it after the FROM/JOIN defining `e`), never a correlated `EXISTS` in a FILTER (planner cannot decorrelate it: 2 x 169k probes, 4-17 s fleet read, 2026-10-08); no bind so re-interpolation is safe. Five sites: `queryGroupedStats` (both branches), `queryStats`, `computeStepStats`. **Any new fixture needs `esDelivered`/`rsDelivered`/`delivered`** (a mock returns 0 for an absent column). Guard "delivered is attributed to the send" in `stats.test.ts`.
- **`groupBy=day` timezone: bind the PRIMARY IANA name** (Postgres resolves against host tzdata; Debian's `tzdata-legacy` carries links like `Asia/Saigon`, `Asia/Calcutta`, `Europe/Kiev`, `US/Pacific`, `Japan`; a missing one throws `time zone "X" not recognized` 22023). `canonicalIanaTimezone` (`src/lib/timezone.ts`) in `localDayKey` AND both `/stats` handlers (cache key collapses aliases); `Intl` alone is not enough (ECMA-402 leaves `Asia/Saigon`), so the explicit `LEGACY_IANA_TIMEZONE_ALIASES` table is the source of truth. Never pass `parsed.data.timezone` straight into a day-bucket query. Tells: DATA-DEPENDENT (evaluated per row; a filter matching nothing returns 200), a 500 from the handler catch not a 400. An unknown zone now returns 400 naming `timezone`; other aggregation failures carry `detail` in the 500. Guard `timezone.test.ts` + `stats.test.ts` pair/shape tests.
- **Campaign-fact gold (`contacted`/`notSending`/`cancelled`) buckets the SAME rows as the cumulative count**: `queryCampaignAggregates` / `queryGroupedCampaignAggregates` bucket `instantly_campaigns` by `localDayKey(c.created_at, tz)` so day-sum == cumulative; do NOT re-source from another table. **`queryGroupedStats` UNIONs aggregate-only keys for EVERY grouping dimension** (`audienceId`, `campaignId`, `featureSlug`, `workflowSlug`, `brandId`, `leadEmail`, `day`), else a freshly started audience read `contacted = 0`; synthesized groups carry real campaign counts and zero event metrics; do NOT re-gate on `groupBy === "day"`. The aggregates query has no `e` alias: its group column is `CAMPAIGN_GROUP_BY_COLUMNS` (`leadEmail` to `c.lead_email`). Guard: groupBy-day tests in `stats.test.ts` (call order [events, aggregates, sentiment]).
- **Emit the parameterized `localDayKey` fragment EXACTLY ONCE per query: name it `group_key` in a CTE and reference the alias; NEVER interpolate `${groupCol}` more than once, and NEVER inside a `--` comment** (drizzle re-emits the timezone bind on every interpolation, including in comments: `42803` when SELECT and GROUP BY placeholders differ, `08P01` when a comment adds a bound param). All three grouped day queries use the CTE shape; non-day groupings keep inline (`sql.raw`, param-free). Mocks cannot catch param drift: the guard is the static SQL assertions (`AS group_key`, `FROM grouped_campaigns c`, `GROUP BY c.group_key`, not `GROUP BY 1`, not `GROUP BY TO_CHAR`). Any new grouped day query needs the same shape.
- **`emailStats.queued` on `GET /orgs/stats` + `/public/stats` (2026-10-04, dashboard "Queued" card)** = emails scheduled and not yet sent for the scope RIGHT NOW: `COUNT(DISTINCT step)` of `sequence_costs status='provisioned'` per per-lead campaign (hold match = `matchesHoldCampaign`), on LIVE sequences only (`c.status='active' AND c.delivery_status IN ('contacted','sent')`, the forecast/reconcile `pendingSends` gate), same scope params + `campaignExclusionClause` as every figure (`queryQueuedEmails` / `queryGroupedQueuedEmails`, `analytics.ts`). Snapshot: per key on non-day groupings, ABSENT on `groupBy=day`, not on `POST /orgs/stats/grouped`. Failed read = `null` (logged), never 0. Issued LAST in its `Promise.all` so mock call order is unchanged. Residual: a campaign-service stop is reflected once the dispatch tick's stopped-campaign sweep pauses the rows. Guard: "emailStats.queued" in `stats.test.ts`.
- **Webhook event normalization**: Instantly emits `link_clicked` (the one event without the `email_` prefix); `promoteFromWebhookPayload` MUST run `normalizeWebhookEventType` (alias `link_clicked` to `email_link_clicked`) before `promoteEvent`; bronze keeps the raw name. Every silver reader uses `email_link_clicked` (gold queries, `computePredecessors`, `backfill-inferences.ts`, `retry-stuck.ts`). Add any new prefix-less event to `WEBHOOK_EVENT_TYPE_ALIASES` + a unit case. Guard in `silver-promote.test.ts`.
- **Silver inference (synthetic predecessors)**: a downstream event synthesizes missing predecessors (`email_opened` N: `email_sent` N; `email_link_clicked` N: `email_opened` N + `email_sent` N; `reply_received`/`email_bounced`/`lead_unsubscribed` N: `email_sent` N; `email_sent` N: `email_sent` 1..N-1). Rows `inferred=true`, `source='inferred'`, `inferred_from_event_id`, `inferred_rule`, timestamp = trigger's. At-most-1-per-step types (`email_sent`, `email_bounced`, `lead_unsubscribed`, `reply_received`) have partial unique index `instantly_events_one_shot_dedupe_idx`; a real event arriving later UPGRADES the row in place (`inferred` false, real timestamp wins, side effects fire then). **Side effects on inferred events are SKIPPED.** `npm run backfill:inferences` is CLI only, never boot.
